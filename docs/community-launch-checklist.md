# Community launch checklist

This checklist is for sharing Aakd publicly. It is an evaluation and feedback
loop, not a promise of customer adoption or a substitute for Phase 0 evidence.

## Before posting

- [ ] A clean machine can run the documented Docker setup.
- [ ] The README explains one workflow in plain language.
- [ ] A real or redacted contract can reach a cited, reviewed obligation.
- [ ] AI involvement and current limitations are stated clearly.
- [ ] No unsupported compliance, security, customer, or autonomous-agent claims appear.
- [ ] The repository license and deployment requirements are visible.
- [ ] The destination community's current rules and launch thread are checked.
- [ ] Any Aakd affiliation is disclosed.

## Post format

Lead with the problem and the observable result:

> We wanted a self-hosted way to turn an executed contract into reviewed
> obligations with owners, dates, and source citations. Aakd is an open-source
> implementation of that workflow. The current release handles PDF/DOCX
> upload, review, obligations, and optional signing. We are looking for
> feedback on setup and trust, not asking anyone to buy it.

Show one short screen recording or a small sequence of screenshots. Explain
what works today, what remains paused, and how to reproduce the workflow.
Avoid broad claims such as replacing legal teams, autonomous legal review,
formal compliance, or enterprise readiness.

## Measure the outcome

Record these separately from GitHub stars:

- repository visits and clone activity;
- clean-install completions;
- first real contract upload;
- first reviewed citation or obligation;
- second workflow cycle;
- actionable issues from operators;
- external contributors;
- qualified organizations and paid validation conversations.

Stars are a reach signal. Activation, repeat use, contribution, and qualified
commercial evidence are product signals.

## After posting

- Answer setup and workflow questions with reproducible details.
- Correct inaccurate claims publicly and update the README when needed.
- Do not request private contracts, credentials, or production access in a
  public thread.
- Convert promising operator reports into the Phase 0 evidence ledger with a
  source link, role, workflow, consequence, workaround, and confidence label.
